DSH 插件机制

加载与依赖注入

DSH 用 Cordis 装配插件。模块声明自己需要哪些服务，依赖就绪后，宿主调用插件入口，把能用的服务交给它。

inject · apply(ctx, config)
前者声明依赖，后者是启动入口。ctx 是当前模块访问宿主能力的入口。
ctx.provide() · ctx.get()
按名称提供、获取服务。一个插件包内的多个模块也可以这样配合。
ctx.inject(依赖, 回调) · ctx.effect()
服务就绪时运行回调；通过 effect 登记资源的清理动作，在卸载时释放。

Loop 例子　会话同步模块依赖 DSH 的会话服务，也依赖 Loop 自己提供的写入器。两项都就绪后，它才开始监听消息。

装配清单 ↗服务提供方 ↗同步模块入口 ↗

事件与回调

ctx.inject() 等服务就绪；ctx.on(事件名, 回调) 等运行中的事情发生。这个项目直接监听了下面这些事件。

DSH 事件何时触发Loop 怎么用
session/created会话建立识别新会话所属的工作区。
session/event事件已写入会话日志观察新消息，按设置安排同步。
session/flush会话要求刷新提示写入器处理待发记录。
session/disposed会话退出活跃状态清理该会话的模型或协作资源。
agent/pre-stepAgent 即将开始一步检查本轮选择，把 Skill 说明补进模型上下文。
tools/execute工具即将执行接手 Loop Proxy 虚拟命令；普通命令交回 DSH。
connection/reset客户端连接重置让模型设置界面重置连接相关状态。
dispose插件卸载移除监听、停止连接和重试。

读回调时看有没有 next。　session/event 通知插件一件已经发生的事。agent/pre-step 和 tools/execute 则让插件参与处理：调用 next() 可以继续后面的流程，也可以接手并返回结果。

会话事件 ↗步骤回调 ↗工具回调 ↗

界面扩展

DSH 在侧栏、面板和输入框预留扩展位置。插件只需登记组件或候选来源，界面由 DSH 统一呈现。

ctx.slots.inject() · ctx.slots.register()
选择界面插槽，登记要显示的组件。
ctx.inputTriggers.registerSource()
给 / 或 @ 等输入入口增加候选项。
ctx.layout.selectPanel() · ctx.uiSession.registerPendingInteraction()
打开指定面板，或在会话中呈现待用户处理的交互。

Loop 例子　侧栏的「任务」来自插槽；输入 / 看到的团队 Skill 来自候选源；聊天里的个人授权提示来自待处理交互。

界面注册 ↗

模型、Skill 与工具

模型、操作指南和可执行工具各有注册入口。插件可以只接入其中一种。

ctx.llm.registerAdapter()
注册模型路由和适配器。DSH 把相应的推理请求交给适配器，接收流式回复。
ctx.skills.register() · ctx.systemPrompt.context()
登记可按需读取的 Skill；也可以按当前会话补充系统提示。
ctx.tools.register()
注册模型能直接选择的工具，可通过 when 限定在哪些会话可用。

Loop 例子　派工是 Loop 通过 ctx.tools.register() 注册的工具。查询任务时用到的 loop-proxy 虚拟命令走另一条路：插件在 tools/execute 回调中识别命令，把查询结果作为 DSH 工具结果返回。

模型适配器 ↗Skill 注册 ↗协作工具 ↗

会话、日志与外部消息投递

DSH 允许插件读取已有会话，也允许插件把外部消息交给指定 Agent 继续处理。

ctx.workspaceRegistry.list() · ctx.sessions.get()
查工作区中的会话，取得活跃会话实例。
session.snapshotEvents() · ctx.sessionQuery.observeSession()
读取活跃会话的一段日志，或只读打开已保存的会话。
ctx.sessionProjections.register() · stateOf()
从事件整理出可查询的状态。Loop 用它判断一条投递是否已有回执。
ctx.agents.get() · sessionController.resolveAgent() · agent.send()
找到或恢复原会话的 Agent，把新消息送进当前轮的下一步或下一轮。

Loop 例子　测试 Agent 在 Loop 任务里回复后，插件从 Loop 的协作连接收件，核对绑定、权限和回执，再调用 DSH 的 agent.send()。派出的任务默认推送反馈；话题要为该话题开启推送。即使协作面板关着，原 Agent 也能接着工作。

会话读取 ↗外部消息收件 ↗Agent 投递 ↗

客户端与宿主通信

客户端需要宿主数据时，通过 DSH Remote 发起调用。它既能返回一次结果，也能在客户端订阅后持续返回更新。

ctx.typert.register() · ctx.remote.$mount()
宿主登记方法描述，客户端挂载声明，随后可以按名称调用。
mode: "stream"
把远程方法声明为流式调用。客户端打开后逐条接收，离开时用取消信号结束订阅。
ctx.remote.$on(事件名, 回调)
监听 DSH 已有的远程事件，例如模型目录更新。
本项目监听的 5 个 DSH 远程事件
  • 模型：llm/adapters-updated、llm/models-updated
  • 设置：settings/document-updated
  • 凭据：credentials/record-updated、credentials/reference-updated

Loop 例子　Loop 用 DSH 的流式机制定义了三个方法：humanTaskEvents 更新授权提示，skillCatalogEvents 更新目录，collaborationEvents 更新协作面板。这里的接收者都是客户端界面。

流式方法声明 ↗客户端挂载 ↗授权提示订阅 ↗

凭据与宿主连接

插件还可以复用 DSH 管理的登录凭据和 Web 连接信息。

ctx.get("credentials")
取得 DSH 凭据服务，供插件宿主端维护登录连接。
ctx.webServer.getOrigin() · ctx.connection.authenticatedUrl()
取得 DSH Web 服务地址，并为指定地址生成认证连接信息。

Loop 例子　Loop 的业务调用复用宿主管理的凭据。启用 Worksite 时，插件用 Web 连接信息把当前 DSH 宿主接到远程工作站。
