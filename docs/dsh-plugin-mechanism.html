插件如何分工

plugins/loop-dsh/lib 是完整 Loop 插件中的会话同步模块。它在 DSH 进程内接收事件、读取会话并转换记录。账号、工作区绑定和持久化上传由同一插件包的其他模块提供。

宿主 · DeepSeek Harness产生会话事件管理工作区与会话，通知插件消息到达，提供会话日志和遥测记录。
适配 · loop-dsh/lib选取并转换监听事件、检查策略、按会话排队，把可同步的内容映射为 Loop 事件。
业务 · Loop 原生插件确定去向并交付Host 服务核对身份和绑定，Writer 按连接配置持久化待发记录并处理上传。

构建完整插件时，build-native.mjs 把这六个文件复制到包内的 sync/。受管配置通过 @pingkai/loop-dsh/sync 装配它，由 sync.mjs 转出入口。

装配与生命周期

DSH 使用 Cordis 装配插件。配置补丁把模块加到插件树，模块通过导出项描述自己，宿主在依赖就绪后调用 apply(ctx, config)。ctx 让多个插件共享服务和事件。

// index.js 中的插件声明
export const name = "loop-dsh-sync"
export const inject = ["sessions", "workspaceRegistry", "sessionQuery", "loopNativeSyncWriterFactory"]
机制在 Loop 中的用法
配置 · Config用 Schemastery 声明必填项、默认值和范围，apply 内再用 resolveConfig 校验 profile 并规范化路径。
提供与获取 · ctx.provide / ctx.getLoop 的 managed-native-actions 注册 loopNativeSyncWriterFactory，同步模块按名取出工厂并创建 writer。前三个 inject 项来自 DSH，第四个来自 Loop。
延迟接入 · ctx.injectloopHostService 已存在时直接绑定，否则等服务可用时再注册连接与会话失效监听。缺少采集策略时按未登录处理。
订阅与释放 · ctx.on / ctx.effect会话回调挂在当前插件上下文。插件卸载时，effect 的清理函数移除 Loop 服务监听；遥测协调器转调 sink.shutdown()，后者等待调度结束并关闭 writer。

跟踪一条消息

假设用户已登录，当前会话属于已登记的 DSH 工作区，在开启会话同步后输入「请整理今天的讨论」。默认模式下发生以下调用。

  1. 宿主通知。 DSH 触发 session/event(session, event)。插件确认登录状态与会话归属，在容量允许时暂存事件，并安排后台任务。
  2. 确认目标。 调度器调用 Loop 的 sessionSyncTarget(session.id)。Host 核对账号、会话同步开关、服务地址、绑定版本等，返回连接配置 profile 和包含账号、工作区、Agent 等信息的 pendingContext。
  3. 转换记录。 插件逐条交给遥测协调器。协调器复制事件、经过宿主的遥测处理回调，再调用插件的 sink.emit(record)。
  4. 交给写入器。 映射器确认是用户发出的可见消息，将正文和稳定的来源标识交给 writer.enqueue()。flushHint() 提示写入器推进发送；此时的 queued 表示已排队，服务端接收由后续上传流程确认。
// 同一条消息的关键字段（示意，省略其他字段）
DSH   user/message    seq: 12    source.kind: "user"
      content: [{ type: "text", text: "请整理今天的讨论" }]
Loop  kind: "human_message"      state: "completed"
      content: "请整理今天的讨论"
      sourceEventId: "dsh:session-demo:4:12"

典型 API 与回调

提供方接口或回调在本例中做什么
DSHsession/created允许历史回补时，检查新会话归属并安排采集。
DSHsession/event收到会话和原始事件。默认模式暂存符合条件的新事件，历史模式安排读取日志。
DSHsession/flush · session/disposed前者提示 writer 刷新；后者在历史模式下安排最后一次读取，并提示刷新。
DSHworkspaceRegistry.list()从工作区的 sessionIds 判断归属，并枚举需要回补的会话。
DSHsessions.get(id) · session.snapshotEvents(from, through)取活跃会话，按左闭右开区间读取日志片段。
DSHsessionQuery.observeSession(id, {projectionMode: "none"})只读观察非活跃会话，读取 header、cursor、events，完成后释放观察对象。
DSH 遥测库new SessionTelemetryCoordinator(ctx, sink, options)选择 on-demand 模式；记录经 session-telemetry/record 处理后送入 sink。此处理点可以挂载脱敏规则。
Loop 实现的回调sink.emit / flush / shutdown把遥测记录转换并入队、提示刷新、等待调度器和 writer 关闭。
Loop HostsyncCapturePolicy() · sessionSyncTarget(id)分别回答“采用什么采集策略”和“该会话此刻可以发到哪里”。
Loop HostcurrentSyncProfile() · addServerProfileListener() · addSessionInvalidationListener()读当前连接、跟随连接切换、处理解绑等会话失效通知。
Loop Writerenqueue() · flushHint() · setActiveProfile() · fenceSessions()按目标入队、推进发送、切换活动连接、隔离失效会话。

写新插件时要留意的方法： 本例调用 coordinator.captureEvent(session, event)，以便只交付已通过准入的单条事件。当前安装的遥测包 0.2.2-rc.1 在 JavaScript 中可调用此方法，但类型声明将它标为 private。公开的按需方法是 captureSession(session, throughSeq?)，它从游标读取一段日志，两者的采集范围不同。

同步策略与故障处理

默认 · 只采集登录期间的新事件事件到达时检查登录和工作区归属；通过会话准入后消费暂存队列。之后登录不会触发补读此前的本地日志。
显式开启 · 回补断连期间的历史枚举工作区会话，通过准入后读取日志。活跃会话取快照，非活跃会话只读打开。按序号记录本轮进度，分批继续。

includeHistory: true 是协调器配置。用户是否允许回补由 Loop 的 uploadDisconnectedHistory 决定，准入发生在读取历史之前。

情形实现行为
消息密集到达同一会话合并为一个后台任务；每次最多处理 64 条，并受 writer 剩余容量约束。未完成任务移至队尾，让其他会话也能继续。
目标未就绪或采集失败上报 failed，调度器从 1 秒起指数退避，最长 60 秒。连接变化可以触发立即重试。
默认模式的暂存队列已满本次新事件不进入暂存队列，会话状态标为 failed。默认策略不会从磁盘自动补回该事件。
账号、连接或绑定变化用递增的代次标识拦住过期的准入或历史读取结果。连接变化重置游标，按条件清除暂存事件；会话失效时清除相应状态并通知 writer 隔离待发记录。

哪些内容会进入 Loop

遥测输入Loop 输出选择规则
user/messagehuman_message仅 source.kind 为 user，且有可见内容。
assistant/messageagent_message取可见文本；图片、文件块转为附件占位文字。用户消息使用相同的内容提取规则。
tool/calltool_started记录开始、合规的工具名及允许的资源引用。仅从参数中提取匹配的资源标识。
tool/resulttool_completed记录成功或失败，从 meta 提取允许的资源引用；原始工具输出不进入映射结果。
turn/end 或 ops 通道提示刷新不生成对话消息。其他未识别事件跳过。

映射器要求有效的会话标识及正整数事件序号。来源事件 ID 由会话、格式版本、序号构成，重放时可沿用。可见文本按 UTF-8 字节取前 32 KiB；工具资源引用按允许的键名和 ID 格式筛选、去重排序，最多保留 32 个。

思考块和附件字节不在选取范围内。用户主动写入可见正文的路径、令牌等仍可能随正文同步；visibleContent() 本身没有对自由文本逐项脱敏。

六个源文件

文件职责及使用位置
index.js ↗插件入口。声明配置与依赖，注册四类会话回调，衔接策略、准入、遥测协调器和 writer。
gate.js ↗SessionSyncGate 负责按会话合并任务、后台轮转、退避、主动重试和关闭。
map.js ↗把遥测记录映射为 Loop 事件；还提供 Loop 工作请求 ID 的编码和解析工具，当前同步入口未调用这两个工具。
config.js ↗校验 profile 和必填 workspaceRoot，解析路径、标签和队列参数。默认 profile 为 dsh-loop，队列上限 10,000，关闭超时配置为 60 秒。
scope.js ↗sessionInWorkspace() 将会话 cwd 与指定根路径解析后比较。同步入口实际使用工作区注册表中的 sessionIds。
label.js ↗bridgeSessionLabel() 将基础名称和外部会话 ID 的 SHA-256 前 16 个十六进制字符组成标签。当前同步入口未调用。

从同步扩展到完整插件

同一套装配机制还支持其他能力。完整 Loop 插件把它们放在独立模块里，各自在需要的宿主扩展点接入。

能力同一插件包里的另一个实例
凭据服务managed-native-actions.mjs ↗ 获取 DSH 的 credentials provider，交给原生 Host 操作层使用。
Agent 步骤与 Skillhost-loop-skills.mjs ↗ 订阅 agent/pre-step；host-service.mjs ↗ 在 skills 服务可用时注册 Harness Skill。
模型接入host-models.mjs ↗ 注册 Loop 模型运行时，根据连接设置刷新，并在会话释放时清理对应资源。
客户端调用 Hosthost-service.mjs ↗ 通过 ctx.typert.register() 登记远程调用描述，使客户端能按已声明的协议调用 Host 能力。
