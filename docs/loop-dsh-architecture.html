一个 DSH 会话，如何连到团队工作区？

用户在 DSH 对话里问「这个任务进展如何」，模型可以理解问题，但任务的最新状态和访问权限都在 Loop。插件把这两端接起来，并让查询结果回到发起它的那次对话。

架构全景

DSH 管理界面、模型运行和本地会话。Loop 管理团队身份、权限和业务数据。安装到 DSH 的插件包含两部分：用户看得见的界面扩展，以及在 DSH 宿主进程里工作的 Host。下文的「Host」指后者。

这些部件怎样装到一起？

DSH 读取插件包的装配清单，加载客户端扩展和各 Host 模块。模块声明需要的服务，由宿主把它们接起来。例如，原生操作模块提供「同步写入器」，会话同步模块取得它后就能提交记录。关闭插件时，Host 释放监听、连接和运行资源；退出 Loop 账号另有撤销流程。

登录之后，一次对话如何找到正确的频道？

例如，同一位用户同时打开「产品」和「交付」两个本地工作区。即使模型在提示词里看到了另一个频道的名字，Host 仍从当前会话查找绑定。重连后遇到过期绑定时，插件向 Loop 核验原归属；目标频道或 Agent 不符会阻止恢复。已修复的操作路由和原会话的上传同意分别管理。

Loop Proxy 如何帮 Agent 查到任务？

「帮我看看刚才提到的任务，现在是什么状态。」

Loop Proxy 给模型一套很小的操作词汇。模型可以先发现现有动作，再询问某个动作需要什么参数，最后对一个具体对象执行。下面沿用插件内置指南的例子，任务 ID 是占位符。

loop-proxy actions task.
loop-proxy schema task.get
loop-proxy call task.get {"taskId":"<已取得的任务ID>"}

普通工具调用继续走 DSH 自己的处理流程；属于 Loop Proxy 但格式无效的命令在本地返回错误。guide 可读取随包操作指南，context 可检查当前连接。模型用这些信息组织请求，长期登录凭据由 Host 管理。

如果 Agent 的权限不够

先用 Agent 自己的权限。对支持个人委托的操作，助手可在原聊天里提出具体授权请求。用户打开 Loop 核对动作、资源、有效期和复用范围，确认或拒绝后，原任务收到决定。已安装应用的委托还要限定到具体应用及动作。

派工为何比查任务多一条回路？

「请让测试 Agent 复核这份发布清单，完成后告诉我。」

查询可以当场返回，派工还要处理对方稍后交回的结果。参与者、允许分享的范围和已创建的任务，因此都要有记录。

如果提交后恰好断线，Host 会保留「结果待核对」的记录，先查这次操作的结果。这样能避免把同一份发布清单再派一次，也能避免把迟到的回复接到另一项任务上。

同一条消息，怎样成为 Loop 中的会话记录？

即使用户只说「稍后再看」，没有发起任何业务动作，DSH 也会产生会话事件。后台同步模块订阅这些事件，独立判断这一条能否上传。因此，能在聊天里查任务和已同意上传这段聊天是两个决定。

先选内容与目标

默认采集登录期间观察到的新事件。Host 核对该会话的同步开关、账号和工作区绑定后，映射器提取可见消息、附件占位或工具状态。开启历史回补后，才会按条件补读本地日志。

再持久化与交付

写入器按原连接记录待发事件，分批提交并处理确认。暂时断线时保留已持久化的待发记录；连接或会话失效时隔离旧工作，避免改发到新账号。界面可据队列与上传状态展示进度。

还有哪些能力接在 DSH 上？

模型选择器
插件获取授权可见的 Loop 模型目录，登记到 DSH 的原生选择器。用户选中模型后，Host 为推理获取短期模型会话，把流式回复送回 DSH。工具调用和模型推理分别走业务动作和模型通道。
Skill 与知识库
例如用户输入「/」选择团队周报 Skill。插件在模型开始这一步之前核验选择，读取指定 Skill，把说明交给模型。选知识库时则限定本轮检索范围，再按权限取资料。选择器让用户指定来源，访问资格由 Loop 决定。
任务与业务页面
用户从侧栏进入任务、项目等入口。客户端通过已声明的远程接口向 Host 申请页面会话，再在 DSH 面板内打开 Loop 页面。页面使用自己的登录状态，长期凭据留在 Host。符合条件的资源链接可跳转到相应面板。
Worksite 远程访问
配置 Worksite 地址后，插件向受信的 Loop 中继登记当前 DSH Host，建立承载网页请求和实时连接的通道，使获得授权的远端用户能访问这个 Host。它解决「怎样从远端打开 DSH」；Loop Proxy 解决「当前 Agent 怎样调用 Loop 动作」。
