DSH 插件机制

第一次使用：安装、登录、找到入口

  1. 安装插件。在插件发布页下载 loop-dsh.tgz，保留压缩包。在 DSH 桌面端打开「插件 → 添加插件 → 安装第三方插件」，填入文件的完整路径，按提示完成安装并重启。 插件发布页
  2. 连接自己的团队。在 DSH 左下角打开「更多 → 登录」，填写团队的 Loop 服务地址，选择工作区，在浏览器完成授权，然后回到 DSH。
  3. 打开一个对话。要用团队模型，在 DSH 的模型选择器里选一个已获授权的 Loop 模型。想看与自己有关的工作，点侧栏「任务」；项目、知识库、云盘和工作流等页面可以从「更多」进入。

安装时 DSH 做了什么？它按包的声明加载模块，等模块需要的服务就绪后调用 apply(ctx, config)。插件通过 ctx 取得侧栏、工具或会话等服务，在对应位置登记自己的功能。

在对话里怎么用

派一件有交付物的工作

「请让测试 Agent 复核这份发布清单，把遗漏项写回任务，并在这个对话里告诉我。」

你可以输入 @ 选人，也可以在这句话里写清负责人。普通提及只选中对象。明确派工后，助手核对当前频道、负责人和可分享的内容，再创建并分配一个 Task。拿到任务编号，表示 Loop 已接单。之后问「这项任务进展如何」或要求补充检查项，助手可沿同一编号跟进。

开一个话题征求意见

「在发布频道开个话题，请测试和运维两位 Agent 讨论回滚方案。有新回复就带回这里。」

助手在指定频道建话题，按你的要求为这个话题开启推送，再把问题发给参与者。派出的 Task 默认会推送反馈；新建话题需要为该话题选择接收方式。话题用 push 时，参与后的可见回复可以回到原会话；用 pull 时，助手按需读取。直接订阅整个频道时，推送还要求消息中有有效提及。

查资料、用团队写法、保留对话

指定材料或写法
在输入框输入 /，选择知识库或 Skill，再说「请按刚选的周报 Skill 写一份草稿」。DSH 在模型开始这一步前调用插件，插件核验选择，把指定 Skill 的说明加入本步消息。选择知识库时，助手按你的选择和已有权限查资料。
查询一个已知任务
直接问「这个任务的负责人是谁？」。模型可以通过 Loop Proxy 查询。DSH 在执行命令工具前触发 tools/execute，插件识别虚拟命令、向 Loop 请求数据，再返回工具结果。用户只需提问。
控制哪些对话传回 Loop
在当前会话的同步设置里查看「同步此会话到 Loop」及目标位置。允许同步后，插件观察 DSH 新增的会话事件，选取可见消息等记录并排队上传。默认只采集登录期间观察到的新事件，补传未登录期间的聊天需要单独开启。

需要个人权限时，助手先尝试自己的权限。遇到支持委托的动作，原对话里会出现授权请求；你可以前往 Loop 核对动作、资源和期限，再决定是否允许。

DSH 接口与回调速查

前面的例子用到了三种接法。插件可以向 DSH 登记能力，等 DSH 在某个时刻回调插件，也可以主动调用 DSH，让界面或 Agent 接着工作。按用途展开即可看到代码中的名字。

插件的装配与生命周期
接口或事件项目中的用法
inject · apply(ctx, config) · Config声明依赖、接收宿主上下文、定义配置。客户端和宿主端各有自己的入口。
ctx.provide() / get() / inject()发布服务、查找服务，或在依赖可用时再接入。插件的会话同步模块通过这一机制取得写入器。
ctx.on() / ctx.effect()登记回调和清理函数。卸载时，插件撤下自己注册的监听和连接。

会话、日志与工作区
接口或事件项目中的用法
session/created · session/event · session/flush · session/disposed会话创建、新事件写入、需要刷新、会话退出活跃状态时，DSH 调用相应监听器。插件在这些时机安排采集和清理。
ctx.workspaceRegistry.list() · ctx.sessions.get()找到会话所属的工作区及其活跃实例。
session.snapshotEvents() · ctx.sessionQuery.observeSession()读取活跃会话的日志片段，或只读观察已保存的会话。
ctx.sessionProjections.register() / stateOf()从会话事件整理出投递回执，查询某条协作消息是否已处理。
ctx.agents.get() · sessionController.resolveAgent() · agent.send()取得活跃 Agent，必要时尝试恢复原会话，再把获准的外部反馈送到它的下一步或下一轮。

接口或事件项目中的用法
